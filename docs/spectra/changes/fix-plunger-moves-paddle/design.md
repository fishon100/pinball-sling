## Context

滑板模式的指標處理在 `game.js`：按下（pointerdown）設定滑板目標並在球於發射道時開始拉桿；整個視窗的移動（pointermove）先算拉桿力道，再設定滑板目標。拉桿時記錄了是哪根手指（`G.plunger.drag.id`），但設定滑板目標時沒有用到。

## Goals / Non-Goals

**Goals:**

- 拉發射桿的那根手指不會帶動滑板；放開後恢復

**Non-Goals:**

- 不改拉桿的力道算法與經典擋板模式
- 不改鍵盤操作

## Decisions

### Plunger Pointer Does Not Steer

在設定滑板目標前檢查：如果正在拉桿（`G.plunger.holding`），而且這個事件的指標就是拉桿的那根（`G.plunger.drag.id === e.pointerId`），就不改滑板目標；按下時如果這一下會開始拉桿，也不設定滑板目標。
替代方案：拉桿時整個滑板鎖住 → 多指觸控時另一根手指就不能先移動滑板，不採用。

## Implementation Contract

- 行為：拉桿中，那根指標的按下與移動不改 `G.world.paddle.target`；放開後下一次移動就恢復控制；其他指標不受影響
- 驗收：新增 AC-S31（遊戲流程測試）：球在發射道、滑板目標 180，從最左邊按下並往右下拖，放開前滑板目標維持 180、放開後移動會改變目標；修正前失敗、修正後通過；其他測試維持通過
- 範圍外：經典擋板、鍵盤、拉桿力道

## Risks / Trade-offs

- [玩家習慣先用拉桿的手指順便擺好滑板] → 放開發射後滑板立刻跟回手指，第一球落下前有足夠時間移動
