## Context

`web/street/editor.html` 目前只能改磚牆（v3.7.2）。台面物件（中柱、彈力牆、加速帶、阿鰭）在「台面配置表」裡用座標文字表示，格式由 `SR.LevelCheck` 讀寫。企劃要求這些也能在編輯器直接操作，並選擇了：加速帶與阿鰭也要能改、中柱預設對稱可關、共用台面可選「全部改」或「另存新台面」。

## Goals / Non-Goals

**Goals:**

- 企劃不用算座標，就能擺出新的台面，並在擺的當下知道會不會出問題
- 編輯結果能原樣貼回「台面配置表」

**Non-Goals:**

- 不改遊戲與同步檢查
- 不做編輯器內試玩

## Decisions

### Edit Mode On The Same Page

同一個編輯器頁面加「磚牆／台面」切換，畫面跟磚牆模式一樣（遊戲美術、這一關的磚），台面模式時磚不能點、物件可以拖。
理由：企劃要同時看到磚和柱子的位置才能判斷；做成另一個頁面還要再選一次關卡。

### Mirror Axis At 180

台面中線是 x = 180（左牆 20、發射道內牆 340），對稱位置 = 360 − x，跟 `data.js` 的 `M()` 一樣。對稱開著時，新增或拖曳一顆中柱，對面那顆同步移動；兩顆剛好在中線上（x = 180）時只放一顆。

### Tools And Hit Testing

工具列：選取／拖曳（預設）、＋中柱、＋彈力牆、＋加速帶、阿鰭（開／關）、刪除選取。點擊判定半徑 16 px（手機手指也點得到）；彈力牆有兩個端點把手和整段把手；阿鰭有路線把手（上下拖改 y）和左右兩個界線把手。座標取整數，限制在台面內（x 20～340、y 340～1000）。

### Live Checks Reuse Game Geometry

提醒用遊戲本身的 `SR.Physics.buildTable`／`placeStage` 建出「這個台面＋用這個台面的每一關的磚」，算距離（跟 AC-S19 同一套 46 px 規則）；「檢查卡球」呼叫測試用的 `SR.Tests.stuckProbe`（跟同步時 AC-S7 同一套）。
理由：編輯器說沒問題、同步卻被擋，企劃會很困惑；用同一套程式就不會不一致。

### Shared Layout Choice

台面模式上方顯示「這個台面用在第 …… 關」。預設「直接改」；按「另存成新台面」輸入新代號（預設建議「原代號_關卡」，例如 d_high_35，不能跟現有代號重複），之後的編輯只屬於新代號，複製的那一列也是新代號，並顯示提醒：「請到關卡設定表把第 35 關的台面配置改成 d_high_35」。

### Copy Uses Layout Table Format

複製內容＝台面配置表一列，用 tab 分隔，欄位順序跟試算表一樣；座標格式沿用 `SR.LevelCheck.toRows` 的寫法，貼回後同步會原樣讀回（測試會驗證「複製 → 讀回」一致）。

## Implementation Contract

- 行為：台面模式能新增、拖曳、刪除中柱（對稱可關）、彈力牆、加速帶，調整阿鰭；即時提醒與檢查卡球；共用台面可另存；複製出可貼回台面配置表的一列
- 介面：`window.SR_EDITOR` 增加 `mode`、`layout`（目前編輯中的台面物件）、`addBumper(x,y)`、`moveObject(kind,i,x,y)`、`remove(kind,i)`、`setMirror(bool)`、`saveAs(id)`、`warnings()`、`copyText()`、`stuck()`，給測試與除錯用
- 失敗情況：另存的新代號已存在時不另存並提示；物件拖出台面時停在邊界
- 驗收：新增 AC-S41（遊戲流程測試：在看不見的框架開 editor.html，用 `SR_EDITOR` 驗證對稱新增、關掉對稱、拖曳、刪除、複製格式、另存新台面、離磚提醒），AC-S42（複製出的台面列用 `SR.LevelCheck.validate` 讀回後與編輯中的台面相同）；手機與電腦截圖
- 範圍外：遊戲、同步、試玩

## Risks / Trade-offs

- [手機螢幕小，物件很密時不好點] → 點擊範圍 16 px；被選取的物件會變亮並顯示座標；也可以在選取後用數字欄位微調
- [「直接改」會影響很多關] → 上方一直顯示用在哪幾關，提醒同時列出每一關的問題
