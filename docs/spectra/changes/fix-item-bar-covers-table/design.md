## Context

版面由上到下是資訊列（HUD）、台面區（`#stagewrap`，彈性填滿）、道具欄（`#itembar`）、提示文字。台面畫布的大小由 `fit()` 依台面區的大小計算，但 `fit()` 只在啟動和視窗 resize 時執行；道具欄顯示或隱藏會讓台面區變大變小，卻沒有觸發 `fit()`。

## Goals / Non-Goals

**Goals:**

- 台面永遠不和道具欄、資訊列重疊
- 道具欄變矮、名字一行，台面可以大一點

**Non-Goals:**

- 不改道具效果與桌機版其他版面

## Decisions

### Refit On Stage Area Resize

每一幀（`tick`）檢查台面區高度，跟上一幀不同就執行 `fit()`；道具欄顯示或隱藏、按鈕填好後也立刻執行一次 `fit()`。
替代方案 1：只在 `updateItemBar` 裡呼叫 `fit()` → 實作時發現提示文字之後會變兩行、再次擠壓台面區，只算一次不夠，所以不採用。
替代方案 2：用 `ResizeObserver` 觀察台面區 → 實作時發現分頁在背景、沒有畫面更新時它不會觸發（測試頁的看不見框架就是這種情況），所以改成每幀檢查（讀一次高度，成本很低）。

### Compact Item Bar

道具按鈕高度約 36 px、名字 11 px 不換行（`white-space: nowrap`）、圖示 16 px；數量徽章維持。

## Implementation Contract

- 行為：道具欄出現或消失後，台面在同一幀或下一幀重新調整大小，畫布上下邊都在資訊列與道具欄之間；道具名字一行
- 驗收：新增 AC-S32（遊戲流程測試，把測試框架改成 390×680）；修正前失敗、修正後通過；手機尺寸截圖確認；其他測試維持通過
- 範圍外：道具效果、取得方式、桌機版其他版面

## Risks / Trade-offs

- [ResizeObserver 每次改變都會重設畫布，可能閃一下] → 只在大小真的改變時重設；遊玩中道具欄不會一直開關
