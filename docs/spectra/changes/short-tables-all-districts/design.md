## Context

第 1 區的矮台面（`top` 320）一個畫面看得完，鏡頭本來就不動；第 2～5 區 `top` 是 160／80／0，台面比畫面高，鏡頭會跟著球捲動。企劃試玩覺得鏡頭上下移動難操作、煩躁，而且球從高處落下時鏡頭追不上、玩家來不及反應。

實驗（擬人新手、滑板、第 2～5 區各 9 關 × 2 局，把現有配置等比例壓進矮台面）：

| 區 | 每關掉愛心：現在 → 矮台面 | 每關秒數：現在 → 矮台面 |
|---|---|---|
| 2 | 0.44 → 0.83 | 61 → 45 |
| 3 | 0.83 → 0.44 | 82 → 34 |
| 4 | 0.83 → 0.28 | 95 → 24 |
| 5 | 0.83 → 0.61 | 118 → 32 |

另外 40 關裡有 17 關的彈跳柱會太靠近磚塊，所以配置不能只是等比例縮，要重新擺。

## Goals / Non-Goals

**Goals:**

- 50 關全部矮台面，遊玩時鏡頭固定
- 用企劃選的方式（彈跳柱變少、球變小、滑板變小、磚變硬、加速帶）維持「越後面越難」，並用擬人玩家量到目標
- 第 1 區玩起來完全不變

**Non-Goals:**

- 不改開場與過關演出的運鏡（它們只是短暫拉近、傾斜，結束會回原位）
- 不改經典擋板模式的難度目標（量測以預設的滑板模式為準）
- 不做加速帶的正式美術（先用程式繪製的霓虹箭頭，正式圖之後由美術做）

## Decisions

### All Layouts Use The Short Table

`SR.LAYOUTS` 的每個配置 `top` 都改 320；配置代號（a_／b_／c_／d_）與每區輪替表 `SR.DISTRICT_LAYOUTS` 不變，所以「相鄰兩關不同」「首領關不放阿鰭」維持成立。鏡頭的公式不用改：`top` 320 時鏡頭本來就被夾在 320。

### Fewer Bumpers In Later Districts

起始擺法（量測時可微調，最後的數字回寫到 `data.js` 與數值總表）：

| 配置 | 名稱 | 彈跳柱（左半邊，右邊自動對稱） | 其他 |
|---|---|---|---|
| b_tri | 四柱 | (74, 650)、(116, 700) | |
| b_steps | 階梯 | (70, 640)、(110, 720) | |
| b_fish | 阿鰭 | (70, 716) | 阿鰭 y 652、90 px/s |
| c_pair | 雙柱 | (78, 690) | |
| c_rubber | 彈力牆 | (96, 690) | 彈力牆 y 610～730 |
| c_fish | 阿鰭 | 無 | 阿鰭 y 670、110 px/s |
| d_classic | 經典 | (60, 700) | |
| d_high | 高柱 | (100, 660) | |
| d_tri | 雙柱 | (80, 700) | |
| d_fish | 阿鰭 | 無 | 阿鰭 y 670、130 px/s |

磚塊在第 3 區起會多 1～3 排，若彈跳柱離磚不到 46 px，就往下移，直到 AC-S19 通過。

### Ball Size Per District

新增 `SR.ballRadiusFor(n)`（12／12／10.5／9／9），開關卡時寫進 `world.ballRadius`；`ballRadius(T, world)` 改成「區的半徑 + 大罐加成」。沒有指定時（舊測試）維持 `T.ball.radius` 12。

### Paddle Size By District

`SR.paddleSizeFor(n)`：首領關或第 4、5 區＝S，其他＝M。

### Harder Bricks From District 3

拿掉 v3.5.5 的「第 4、5 區少 1 血」（那是因為高台面一關要 165 秒；矮台面只要 24～32 秒），改成第 3～5 區每塊 +1 血（最多 5）。亂數取用順序保持不變，所以磚的排列跟現在一樣。

### Boost Pads Point Upward

加速帶是 56×14 的長條，箭頭朝上。只有「往上走」的球經過才加速（×1.35、最少 1000、最多 2000、同一顆球 0.5 秒內不重複）。
理由：如果往下掉的球也加速，從加速帶到滑板只剩約 190 px，2000 px/s 只要 0.1 秒，比新手反應時間 0.32 秒還短，等於必死；企劃要的是「變難」不是「沒辦法接」。
替代方案：照球目前方向加速（不分上下）→ 量起來會出現接不到的球，不採用。
位置：第 3 區 1 條在台面中線（x 180、y 770）；第 4、5 區 2 條在左右（x 110 與 250、y 780）。首領關沒有。

### Difficulty Measured Per District

新增測試 AC-S29：第 2～5 區每區 9 關一般關 × 2 局，擬人新手、滑板，檢查「每區不比前一區簡單超過 0.15」「第 5 區 0.8～1.4」「每區平均 ≤ 90 秒」。數值沒達標時依序調整：磚血 → 加速帶倍率 → 球大小 → 彈跳柱位置；每次調整都記在任務裡，最後用 `/spectra-ingest` 把定案數字寫回規則書。

## Implementation Contract

- 行為：50 關都是矮台面，遊玩時鏡頭固定；第 3 區起球變小、有加速帶；第 4、5 區滑板變小；第 3～5 區磚多 1 血；第 2～5 區彈跳柱變少
- 介面／資料：`SR.LAYOUTS[*].top === 320`；`SR.LAYOUTS[*].boost`＝加速帶陣列 `[{x, y, w, h}]`（只在 c_／d_ 配置；首領關建台時不放）；`SR.ballRadiusFor(n)`；`SR.paddleSizeFor(n)`；物理事件 `{ type: "boost", b }`
- 失敗情況：舊測試用的 `DEFAULT_LAYOUT`（高台面）保留給物理測試（AC4、AC-S5 的鏡頭測試），遊戲關卡不再用到
- 驗收：新增 AC-S27（每關 top 320、遊玩時鏡頭固定）、AC-S28（加速帶規則）、AC-S29（第 2～5 區難度）、AC-S30（球大小、滑板大小、磚血、彈跳柱數量）；原有 AC-S7（卡球）、AC-S19（柱離磚）、AC-S20（第 1 區）、AC-S8b（首領）維持通過；全部測試通過後部署，請企劃在手機試玩第 3～5 區
- 範圍外：經典擋板模式的難度目標、加速帶正式美術、Godot 版

## Risks / Trade-offs

- [第 3 區起球變小又有加速帶，可能突然變很難] → AC-S29 限制「每區只比前一區難一點」；企劃試玩後可以再開申請單微調
- [第 4、5 區一般關也用小滑板，首領關就沒有「滑板變小」的特別感] → 首領本身的血量、速度仍然比較高；之後若企劃想要，可以再加更小的尺寸
- [加速帶讓球速變快，可能穿牆] → 上限 2000 低於現有測試的 2600（AC4 已驗證 2600 不穿牆）
