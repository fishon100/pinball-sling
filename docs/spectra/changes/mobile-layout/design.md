# 設計：手機版面（實作版，2026-10-08）

> 原本設計是把物理幾何加寬（左牆 0、發射道 32 px、磚格 39.4）。實作時改成**鏡頭視窗**：物理座標、50 關磚牆、台面配置表、編輯器、關卡工具全部不動，風險小很多，而且磚變大的效果一樣（375 寬手機發射後一塊磚 36 px，原本 29 px，大 25%）。

## 鏡頭視窗（game.js）
- `G.win = { x0, w }`：畫面看台面座標的哪一段；`VW` 改成可變（＝ `win.w`），所有用 VW 排版的疊圖（教學卡、操作卡、STAGE 標題、連擊）自動跟著視窗寬。
- 電腦：永遠 0～400（整個畫布，有外框）。
- 手機（寬 ≤ 520）：發射道有球時 20～380；球離開發射道那一欄（x > 340）後 0.3 秒內收到 20～340（`G.laneK` 0→1）；螢幕比台面寬時左右對稱多看一點牆（`fill = VH × 畫面寬 / 畫面高`），台面永遠貼齊螢幕兩邊。
- render：世界座標先 `translate(-win.x0)`；鏡頭拉近的中心用 `viewCX() = win.x0 + VW/2`（開場運鏡、過關運鏡、物件特寫都改用它）。
- 指標：`toGameX = win.x0 + 比例 × VW`。
- 每次視窗變動就 `fit()` 重算畫布大小（0.3 秒動畫期間每幀一次，畫布不大，成本可接受）。

## 發射道滑出（art.js）
- `A.table(g, world, pal, t, laneSlide)`：玻璃管與右外牆（x ≥ 380 的牆）`translate(laneSlide)`，`laneSlide = laneK × 44`；柱塞在 game.js 同樣平移。
- 發射道滑回前（laneK > 0.02）不畫發射道裡的球，球等發射道到位才出現。
- 物理不變：發射道內牆 x=340 還在原位，球回到發射道的路徑一樣。

## 版面（index.html）
- `@media (max-width: 520px)`：`.app` 無左右留白、畫布無邊框／圓角／陰影、`.hud` 絕對定位半透明疊在最上面（含 safe-area）、`.hint` 絕對定位半透明疊在最下面。
- 磚最上排在 375×812 上離資訊列約 60 px，不會被蓋到（AC-S32 量）。

## 磚區多 3 排
- 編輯器與關卡檢查的排數上限 11 → 14；企劃在編輯器「＋ 加一排」即可往下加（離加速帶／中柱 46 px 的檢查照舊）。

## 測試
- AC-S32（375×812：畫布貼齊兩邊、無邊框、資訊列疊在台面上、發射後 laneK＝1、磚 ≥ 36 px、最上排磚不被資訊列蓋到）、AC-S61（711×914 電腦有外框、視窗 0～400）、AC-S62（發射道 0.3 秒滑出／滑回）。
- 其餘遊戲流程測試的框架是 400 px 寬，等於全部在手機模式下跑過。
