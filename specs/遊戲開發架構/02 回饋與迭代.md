# 02 回饋與迭代
> 總覽：[[00 開發架構總覽]]・範本：[[回饋範本]]

## 循環
```
AI 部署 → 電腦＋手機收到通知（附連結）→ 人試玩 → 在專案的「回饋」寫第 N 輪
   → 對 AI 說「看回饋」→ AI 依回饋改功能規劃書 → 寫測試 → 實作 → 部署 → 通知
```

## 回饋怎麼寫
每個專案根目錄有一份 `回饋.md`，每輪一個段落：
```markdown
### 第 N 輪（vX.Y 試玩後寫在這裡）
🔴 必修：……（附截圖）
🟡 建議：……
🟢 很好：……（AI 會保留不動）
```
- 截圖直接貼上；AI 處理時會把圖片移到媒體庫的「參考圖」並重新命名
- 用**命名總表**裡的名字描述（例：「彈跳柱」而不是「中間那個柱子」），避免誤會
- AI 處理完會在標題標「已處理 → 版本」，並開好下一輪的空段落

## AI 處理一輪回饋的固定動作
1. 讀回饋 → 對照命名總表，名詞不清楚的先在回報裡確認理解
2. 找出受影響的**功能規劃書**，只改那幾份（其他不動）
3. 寫／改自動測試 → 實作 → 跑全部測試 → 擬人玩家量難度
4. 部署 → 通知
5. 開發日誌記一筆：回饋 → 改了什麼 → 數據
6. 自己找可以優化的地方，量測證明有改善才做（自主迭代），一樣記錄
