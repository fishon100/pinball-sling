# 01 開發流程（SDD＋TDD）
> 總覽：[[00 開發架構總覽]]

## 核心觀念：人寫規格，AI 做事，測試把關
AI 最怕兩件事：**需求不清楚**（會亂猜）和**沒有標準**（不知道做完沒）。SDD 解決第一個，TDD 解決第二個。

### SDD（Spec-Driven Development，規格驅動開發）
先把「要做什麼、做到什麼程度算完成」寫成文件，再讓 AI 照著做。
- 本架構的「規格」就是：**主架構規劃書**（遊戲核心）＋**功能規劃書**（每個功能一份）→ 見 [[06 專案文件架構規範]]
- 參考工具：[spectra-app](https://github.com/kaochenlong/spectra-app)（討論 → 提案 → 實作 → 併入新需求 → 驗收 → 結案）。沒裝也能照這套文件做。

### TDD（Test-Driven Development，測試驅動開發）
先寫「怎樣算對」的自動測試，再寫程式讓測試通過。
- 適合有明確對錯的：物理（球不能穿牆）、規則（獎牌條件）、資料（對白不超過 32 字）、難度（擬人新手每關 ≤1 顆愛心）
- 不適合「好不好玩」：手感、美術 → **人在手機上試玩驗收**（[[02 回饋與迭代]]）
- 細節：[[05 品質驗收與難度量測]]

## 多 AI 分工
各家 AI 擅長的不同，依工作分派（工具清單見 [[04 工具與環境]]）：
| 工作 | 建議 | 理由 |
|---|---|---|
| 主控：架構、程式、測試、部署、文件 | Claude Code（搭配 `/goal`） | 能直接操作檔案與終端機、自己跑到完成 |
| 第二意見：程式審查 | 另一家程式 AI（Codex、Copilot） | 交叉檢查 |
| 文字：劇本、台詞、文案 | ChatGPT／Claude | 依世界觀批量產出，劇本再修 |
| 圖：概念美術、角色、UI | ChatGPT（GPT Image）、Midjourney、Gemini | 出方向稿，美術在 Figma 精修 |
| 音樂 | Suno | 背景音樂草稿 |
| 音效、語音 | ElevenLabs | 撞擊音、短句語音 |
| 數值 | Claude＋試算表 | 公式、模擬平衡 |

**串接原則**：每個 AI 的產出都要落地成檔案，放進專案的知識庫或媒體庫，下一個 AI 讀檔案接手——不靠人複製貼上。

## 一次功能開發的步驟
1. 企劃寫或修改**功能規劃書**（[[功能規劃書範本]]）
2. 對 Claude Code 下：`/goal 依 <功能規劃書> 實作，測試全過並更新開發日誌`
3. AI：拆任務 → 寫測試 → 實作 → 跑測試 → 擬人玩家量難度 → 部署 → 通知電腦與手機
4. 人用手機打開預覽連結試玩
5. 有問題 → 寫回饋（[[02 回饋與迭代]]）→ 再一輪

## 給 AI 的規則（寫在專案的 CLAUDE.md）
- 手感數值讀設定檔（例：`tuning.json`），不寫死在程式裡
- 任何改動都要跑測試，全過才算完成
- 改了功能 → 同步更新那個功能的規劃書；改了劇情／角色 → 同步知識庫
- 每次完成都通知電腦＋手機，附預覽連結
