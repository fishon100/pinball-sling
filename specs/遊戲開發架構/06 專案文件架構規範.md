# 06 專案文件架構規範
> 總覽：[[00 開發架構總覽]]。每個遊戲專案都用同一套資料夾。範例：`彈珠專案/`。

## 資料夾
```
<專案>/
├─ 00 主架構規劃書.md      ← 遊戲核心（一切變體不離核心）＋功能索引
├─ 回饋.md                 ← 試玩回饋（第 N 輪）
├─ 01 功能規劃書/          ← 每個功能一份，各自獨立
├─ 02 知識庫/              ← 文字類「單一來源」：劇情、角色、世界、數值、名詞
├─ 03 媒體庫/              ← 圖與聲音：美術、音樂音效、參考圖（含清單與製作規格）
└─ 04 紀錄/                ← 開發日誌、歷次版本規格、舊版文件（只看不改）
```

## 各部分寫什麼
| 部分 | 寫什麼 | 不寫什麼 |
|---|---|---|
| **主架構規劃書** | 一句話、核心體驗（設計支柱）、核心循環、不能改的核心規則、功能索引、目前狀態 | 功能細節（放功能規劃書） |
| **功能規劃書** | 目的、玩家體驗、**功能系統**（規則與數值）、**使用的外部工具**、**介面**、**元件**、程式位置、驗收、相關知識庫／媒體、修改紀錄 | 其他功能的細節（用連結） |
| **知識庫** | 劇情腳本、角色卡、世界設定、數值總表、名詞與命名總表；每類寫明「產出工具／管理工具」 | 圖檔、音檔（放媒體庫） |
| **媒體庫** | 素材清單（檔名、規格、狀態、使用位置、AI 提示詞）、風格指南、參考圖；每類寫明「產出工具／管理工具」 | 劇情文字（放知識庫） |
| **紀錄** | 開發日誌、舊版本規格 | 目前的設計（以規劃書為準） |

## 單一來源與同步
「改一個地方，相關地方自動跟著變」靠兩件事：

### 1. 文件之間：嵌入（Obsidian 的 `![[ ]]`）
- 角色外型只寫在**角色卡**；美術風格指南、漫畫系統規劃書用 `![[阿鰭#外型]]` 嵌入 → 改角色卡，所有嵌入處同步更新
- 名詞只定義在**名詞與命名總表**；其他文件用連結 `[[名詞與命名總表#彈跳柱]]`
- 數值只寫在**數值總表**（或該功能規劃書的數值表），其他地方嵌入，不重抄

### 2. 文件與遊戲之間：對照表＋「同步」指令
每個知識庫／媒體庫檔案的開頭都寫明「遊戲裡對應的程式位置」。企劃改了文件後，對 AI 說「**同步 <檔名>**」，AI 會：
1. 把變更套用到對應的程式／資料檔
2. 跑相關測試（例：劇情 → 漫畫版面測試）
3. 部署並通知

| 內容 | 單一來源（改這裡） | 遊戲裡的位置（AI 同步） |
|---|---|---|
| 劇情腳本 | 知識庫/劇情/劇情腳本 | 程式資料檔（例：`data.js` 的漫畫資料） |
| 角色 | 知識庫/角色/<角色> | 角色繪圖程式、對話者名稱 |
| 數值 | 知識庫/數值總表 | 手感設定檔（例：`tuning.js`、`tuning.json`） |
| 名詞 | 知識庫/名詞與命名總表 | 介面文字 |
| 素材 | 媒體庫/<類別>/素材清單 | 遊戲素材資料夾 |

## 改一個功能時
1. 只開那份功能規劃書修改，最下方「修改紀錄」記一筆
2. 如果牽涉角色／劇情／數值 → 改知識庫那份（其他文件靠嵌入自動更新）
3. 對 AI 說「依 <功能規劃書> 調整」→ AI 只改那個功能的程式與測試

## 命名
- 功能 F01、F02…；元件 C-xxx；介面 U-xxx；輔助 A-xxx；角色 CH-xxx（記在名詞與命名總表）
- 功能規劃書檔名：`F01 開場動畫` 這種格式
